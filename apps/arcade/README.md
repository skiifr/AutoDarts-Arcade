# AutoDarts Arcade — app

One Expo + React Native codebase for **iPhone, iPad, Android and the Fire TV Stick 4K Max** (versions in [ADR-003](../../docs/adr/0003-client-stack-versions.md)).

> **Shell build.** Every screen from the wireframes (ARCHITECTURE §10) is here, driven by **demo darts**.
> - Scoring is a placeholder points sum (`src/shell/demo-session.ts`).
> - The real game engine arrives in Phase 3 and the live board connection in Phase 2.
> - Nothing in this build talks to your board.

## Screens

| Route | Wireframe | What works |
|---|---|---|
| `/` | W0 Connect | Demo mode; address field (connect is disabled until Phase 2) |
| `/games` | W1 Game select | Categories, focusable tiles, details panel |
| `/setup?game=…` | W2 Player setup | Add, remove and reorder players; option steppers; start |
| `/play` | W3 Live gameplay | Standings, darts pinned on the board, turn panel, takeout / offline / review / stuck banners, pause menu, demo throw / board clear / autoplay |
| `/fix` | W4 Correction | Pick a dart or add a missed one. Touch: tap the segment. Remote: **OK** to edit, **◀ ▶** number, **▲ ▼** ring (bull → … → double → miss), **OK** done. Live score preview |
| `/victory` | W5 Victory | Confetti, standings, rematch, fix last turn |

## Run it

From the repo root (Node 22.12+, Yarn 1):

```sh
yarn install
yarn web                   # browser preview (Expo dev server)
yarn verify                # lint + typecheck + unit tests
```

In the browser, add **`?input=remote`** to the URL to get the TV treatment: focus ring and 5% overscan margins.
- Arrow keys and Enter act as the D-pad **only on the Fix (W4) dartboard picker**.
- Everywhere else, moving focus between tiles and buttons relies on the TV's native focus engine, which the browser doesn't have. Tab moves through them in page order instead.
- So remote-only navigation must be checked in the **Android TV emulator** or on the **Fire TV stick**.

### On devices

Native builds need a development machine (Xcode for iOS) or EAS Build:

```sh
cd apps/arcade
npx expo run:ios           # iPhone / iPad (Xcode)
npx expo run:android       # Android phone / tablet
EXPO_TV=1 npx expo prebuild --clean && npx expo run:android   # Fire TV (Fire OS) build
```

With EAS (profiles in `eas.json`):

| Profile | Output | Install |
|---|---|---|
| `testflight` | iOS / iPadOS store build | `eas build -p ios --profile testflight`, then `eas submit -p ios --profile testflight` → TestFlight |
| `android-apk` | Android APK | Download and install on the phone or tablet |
| `firetv-apk` | Fire TV APK (`EXPO_TV=1`) | Sideload with `adb install` after turning on ADB debugging on the 4K Max |

`ios/` and `android/` are generated by prebuild and are not committed.

CI compiles the Android phone, Android TV and iOS simulator builds on every push that touches code (`.github/workflows/native.yml`). These are unsigned debug builds that prove the native projects compile.
- The APKs are kept for 14 days as workflow artifacts.
- Being debug builds, they load their JavaScript from the Expo dev server (`npx expo start` in this folder). For a standalone install, use the EAS profiles above.

## Layout rules

- **Wide** (TV, iPad, landscape): the 16:9 wireframe layouts on a 960×540 design canvas, scaled to the screen.
- **Narrow** (phone portrait): single-column versions of the same screens.
- **Remote** input (Fire TV, or `?input=remote`): gold focus ring with a gentle scale, every action reachable by D-pad, 5% title-safe margins.
- **Touch** input: no focus ring; the dartboard is tappable in W4.
